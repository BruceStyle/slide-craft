# Slide Craft · slide工艺

一份slide的成败,在打开任何设计工具之前就已决定大半。本skill把制作组织为**五个阶段**,每阶段有明确关卡;贯穿全程的是两组"律":**审美律**(成品的品质底线)与**协作律**(与用户共创的方式)。

核心信念:slide是拿来讲的,不是拿来读的;打动人的是叙事,留住人的是品味。风格可以千变,工艺标准不变。

## 开工前 · 确认产出与环境

为什么:这两件事不先说清,做到最后才发现对不上,前面的工夫全部白费。

- **产出格式**:本skill的成品是单文件HTML放映稿 + PDF,不是可在PowerPoint里编辑的.pptx。第一轮访谈就向用户说明。用户需要.pptx时,阶段一、二(访谈与大纲)照常使用,成稿改用能生成.pptx的工具,不要用HTML做完再硬转。
- **运行环境**:阶段四的截图自查和阶段五的PDF导出依赖命令行、Python和headless Chromium(脚本在 scripts/,安装见 references/html-deck-kit.md 第0节)。开工前检查一次。不具备时不要假装检查过——改走同一文件第7节的降级方案,并告诉用户哪些检查需要他代做。

## 阶段一 · 访谈与盘点(先听懂,不动手)

为什么:需求方几乎从不在第一句话里说清真实需求。抢跑产出等于返工——宁可多问三轮,不可先做一页。

- 以访谈形式分轮推进,每轮聚焦一个主题、3-5个问题,边听边追问。首轮必问:**观众是谁**(具体到机构类型、立场、内行程度)、**场合与时长**(路演20分钟还是深聊2小时,决定页数与密度)、**会后想拿到什么结果**、**姿态**(进攻/守成/对等)。
- 盘点既有素材:旧PPT、文档、截图、logo全部翻一遍再提问——带着事实提问才有质量,也避免让用户重复提供已有的东西。旧PPT可用 scripts/extract_pptx.py 提取文字与图片。
- 定**口径红线**并写进大纲头部:哪些数据可披露、哪些留口头、哪些需匿名、哪些表述有政治/法律/竞对敏感。此后每页遵守。
- 守**诚实边界**:能力表述只主张真实壁垒(方法、工艺、数据、渠道),不暗示不存在的东西(如把外采的技术说成自研)。内行观众一问便穿,穿一次全场信用归零。

**关卡**:能用三句话说清"观众 × 目的 × 希望他们会后转述的话",才进阶段二。

## 阶段二 · 叙事与大纲(骨架决定生死)

为什么:"自传体"(我是谁、我有什么、都很好)是所有介绍材料的默认引力,必须刻意对抗。对特定观众,叙事应当是 **deal-shaped**——从"对方为什么需要你"倒推每一页的存在理由。

- 先写下**目标感觉**:会后希望观众在内部转述的三句话。整个deck为这三句话服务,写不出就回阶段一。
- 用**幕式结构**组织(可参考:立势→立信→主菜→底盘→成交五幕),幕数与命名按题目定制,不硬套。开场先立"这场会为什么值得开"的行业论断,再介绍自己。
- **主从有别**:对当前观众最相关的业务是主菜,占篇幅;其余压缩为证明实力与稳健的底盘。把所有业务等权重罗列,是叙事失败的标志。
- 为具体观众设**专属页**:一页只对这位观众说的话(如面向地方政府的本地落地页、面向产业方的合作地图页),把对方画进解法。
- 大纲逐页写清:页目的 / 信息点 / 数据锚 / 素材需求 / 讲稿备注(刻意留给口头的"弹药")。大纲**版本化**(v1、v2…),每轮修改留痕。
- **高维审视关卡**:大纲成稿后强制自问——这份叙事能打动这位观众吗?会留下什么感觉?哪一页是"复述页"(信息在别处已出现)?每页的存在理由说不出来,就删或改造。

**关卡**:用户明确认可大纲,才进阶段三。

## 阶段三 · 风格定调(先比稿,后动工)

为什么:风格分歧发现得越晚,返工越贵;而用文字描述风格几乎无效——必须让用户**眼见**。

- **同题比稿**:选deck中最重要的一页(通常是核心论点页,内容含大标题+论据+一个可视化,最能暴露风格差异),做5-6种方向完全不同的完整样稿(例如:编辑排版 / 暗色资本 / 东方留白 / 大字宣言 / 软科技光晕 / 工程图纸),放在一个可翻页的HTML里对比。
- 用户选定方向后,再做**同版式配色比稿**5-6种(可从品牌logo取色、从观众语境取意),同样翻页对比。
- 锁定**设计token**:背景/墨色/辅文色/细线色/强调色/衬底色;字体三件套(中文正文黑体 + 数字衬线体 + 英文标签等宽体);刊头页脚语法。此后所有页面共用一套token,不再逐页发明。

**关卡**:用户选定风格与配色,才进阶段四。

## 阶段四 · 逐页制作(一页一审,绝不批量)

为什么:批量产出全稿再返工,成本是逐页确认的十倍;逐页共审还在持续校准双方品味——越做越快,越做越准。

每页的流程:构思布局 → 写码 → **截图自查**(scripts/check.py,截图后亲眼看) → 修到自己满意 → 呈给用户 → 用户认可才进下一页。

截图自查清单:内容溢出/元素遮挡/图片坏链/与翻页控件冲突/字重层级/间距节奏/标题是否自解释。

用户提出质疑时:不辩解,退一步重新审视这一页的目的——问题常在上游(标题措辞、叙事定位、页面存在理由),而非像素。

全程遵守下方**审美律**;版式细则与改造案例见 references/aesthetics.md。

## 阶段五 · 整稿与交付

- **全deck走查**:用 scripts/check.py 检查坏图、溢出与页数;通览全部页面截图,核对页码、章节标签、交叉引用、语法一致性。
- **双格式交付**:HTML(现场放映,键盘/点击翻页,自适应缩放)+ PDF(传输存档;用 scripts/export_pdf.py 导出,20页控制在5MB级)。
- **目录整理**:终稿与其相对路径引用的素材放同一文件夹,构成可整体拷贝/压缩的自洽交付包;大纲历史、过程稿、原始资料分层归档。
- 交付时附**口头弹药清单**:哪些内容刻意不上页面、留给现场哪一页讲。

## 审美律(每一页都要过的品质关)

1. **每页一个视觉主角**——一张图、一个数字、一句话或一个图表,其余元素让位。信息塞满等于没有重点。
2. **标题自解释**——外人第一遍就能懂。禁内部黑话与未经铺垫的比喻;论证页可用设问("为什么是X?"),结论页用陈述;口水化的句子与过谦的句子都不配占标题位。
3. **图表语义 = 结论**——动笔前先问"这张图的形状本身在说什么"。窗口期是时间轴上的区间,不是曲线末端的一个点;两股相向的力量用双线剪刀差;因果与输送用箭头流向图。形状说错话,数据再对也白搭。
4. **垂直节奏统一**——主区块间距用一个尺度(建议34-42px),把留白摊匀在区块之间;页尾淤积大片空白说明"上密下空",必须重新摊配。
5. **证据贴着主张**——凡主张必有可见证据(数据锚/实拍/证书/客户logo)。实证图(证书、专利、报道)证"真",质感图(实景、产品、现场)证"实感",分工明确。证据在各章已就地安放后,"汇总复述页"信息增量为零——删掉或改造成对观众的专属页。
6. **文案姿态对等**——不吹不跪。"没有您的支持这件事做不成"是跪;"这件事我们已经在做,加上您的渠道能做得更快"是对等。敬语可以有,底气必须有。
7. **页面语法统一**——刊头(章节面包屑+页码)、页脚(幕标签)、右上角mono标签位、强调色衬底,全deck一套语法;唯一允许打破语法的是封面与封底。
8. **克制即高级**——emoji在投影/异机环境有渲染风险且气质廉价,不用;全角字距(letter-spacing)用于中文标签典雅,但会拆散英文词组,需分级设置;一切装饰让位于信息。

## 协作律

- **永不抢跑**:未过关卡不产出下一阶段成品;用户说"先讨论",立即停下构建。
- **挑战即礼物**:用户说"看不懂/不对劲/请重新审视",第一反应是升维复盘(这页为什么存在、标题在对谁说话),而非局部缝补或辩解。
- **版本留痕**:大纲v1→vN、风格样稿、配色样稿全部保留,决策可回溯。
- **敏感自觉**:领导人照片、监管敏感表述、竞对点名、史实日期,主动核查规避,并告知用户规避了什么、为什么。
